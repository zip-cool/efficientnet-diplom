КОНТЕКСТ ДЛЯ CODEX
Проект дипломной работы: исследование упрощения архитектуры EfficientNet
Задача: классификация заболеваний листьев картофеля

==================================================
1. ОБЩАЯ ЦЕЛЬ ПРОЕКТА
==================================================

Необходимо реализовать серию экспериментов, в которых изменяется сама архитектура нейронной сети, построенной на основе EfficientNetB0.

В предыдущей версии проекта использовалась готовая EfficientNetB0 из keras.applications, после чего исследовались разные способы обучения. 
Теперь основная задача должна состоять не в сравнении режимов обучения готовой модели, а в последовательном упрощении 
архитектуры EfficientNet и оценке того, как каждое изменение влияет:

1) на точность классификации;
2) на время обучения.

В дипломной работе будут использоваться только следующие итоговые показатели:

- accuracy на обучающей выборке;
- accuracy на валидационной выборке;
- accuracy на тестовой выборке;
- loss на обучающей выборке;
- loss на валидационной выборке;
- loss на тестовой выборке;
- общее время обучения;
- при необходимости время обучения каждой эпохи.

Дополнительные метрики, такие как precision, recall, F1-score, FLOPs, MACs, время инференса и размер модели, в обязательную 
часть проекта включать не нужно. Но они должны присутствовать в отчетах.

При этом для каждого эксперимента необходимо сохранять не только итоговые значения, но и все исходные данные, по которым строятся графики. 
Это необходимо для того, чтобы после завершения обучения можно было повторно построить график, изменить его оформление, объединить 
несколько экспериментов на одном графике или исправить подписи без повторного обучения модели.

==================================================
2. ОСНОВНАЯ ИДЕЯ РЕАЛИЗАЦИИ
==================================================

Нужно создать собственную параметризуемую реализацию сети на основе архитектурных принципов EfficientNetB0.

Необходимо реализовать:

- отдельную функцию MBConv-блока;
- механизм Squeeze-and-Excitation;
- residual connection там, где совпадают размеры тензоров и stride равен 1;
- масштабирование числа каналов;
- масштабирование количества повторений блоков;
- изменение expansion ratio;
- включение или отключение Squeeze-and-Excitation;
- изменение размеров depthwise-ядер;
- изменение числа каналов в последней части сети;
- изменение входного разрешения.

Желательно, чтобы модель создавалась одной функцией примерно следующего вида:

build_modified_efficientnet(
    input_shape,
    num_classes,
    width_coefficient=1.0,
    depth_coefficient=1.0,
    expansion_ratio=None,
    se_ratio=0.25,
    use_se=True,
    kernel_mode="standard",
    head_channels=1280,
    dropout_rate=0.2,
    model_name="modified_efficientnet"
)

Параметры конкретного эксперимента должны задаваться через конфигурационный объект или словарь, 
а не вручную изменяться в коде перед каждым запуском.

==================================================
3. БАЗОВАЯ АРХИТЕКТУРА
==================================================

В качестве основы необходимо использовать структуру EfficientNetB0.

Базовая конфигурация стадий может быть описана таблицей или списком словарей. Для каждой стадии нужно хранить:

- тип блока;
- kernel_size;
- stride первого блока;
- expansion_ratio;
- input_filters;
- output_filters;
- repeats;
- se_ratio.

Пример логической структуры:

stage 1:
- kernel_size = 3
- repeats = 1
- input_filters = 32
- output_filters = 16
- expansion_ratio = 1
- stride = 1

stage 2:
- kernel_size = 3
- repeats = 2
- input_filters = 16
- output_filters = 24
- expansion_ratio = 6
- stride = 2

stage 3:
- kernel_size = 5
- repeats = 2
- input_filters = 24
- output_filters = 40
- expansion_ratio = 6
- stride = 2

stage 4:
- kernel_size = 3
- repeats = 3
- input_filters = 40
- output_filters = 80
- expansion_ratio = 6
- stride = 2

stage 5:
- kernel_size = 5
- repeats = 3
- input_filters = 80
- output_filters = 112
- expansion_ratio = 6
- stride = 1

stage 6:
- kernel_size = 5
- repeats = 4
- input_filters = 112
- output_filters = 192
- expansion_ratio = 6
- stride = 2

stage 7:
- kernel_size = 3
- repeats = 1
- input_filters = 192
- output_filters = 320
- expansion_ratio = 6
- stride = 1

Перед первой стадией должен быть stem-блок, а после последней стадии:

- свертка 1 x 1;
- BatchNormalization;
- функция активации;
- GlobalAveragePooling2D;
- Dropout;
- Dense с числом выходов, равным числу классов.

Для трех классов выходной слой:

Dense(3, activation="softmax")

==================================================
4. ЕДИНЫЕ УСЛОВИЯ ЭКСПЕРИМЕНТОВ
==================================================

Все архитектурные варианты должны обучаться в максимально одинаковых условиях.

Для всех экспериментов необходимо зафиксировать:

- один и тот же набор данных;
- одно и то же разбиение train / validation / test;
- один и тот же random seed;
- одинаковый batch size;
- одинаковое максимальное число эпох;
- одинаковый optimizer;
- одинаковую начальную скорость обучения;
- одинаковую функцию потерь;
- одинаковую аугментацию либо полное отсутствие аугментации;
- одинаковые callbacks;
- одинаковые правила early stopping;
- одинаковое оборудование, насколько это возможно.

Предварительно предлагается использовать:

- seed = 42;
- optimizer = Adam;
- loss = categorical_crossentropy или sparse_categorical_crossentropy в зависимости от формата меток;
- metric = accuracy;
- batch_size = 32;
- одинаковое максимальное число эпох для всех экспериментов;
- EarlyStopping по val_loss с восстановлением лучших весов;
- ReduceLROnPlateau при необходимости.

Точные значения числа эпох, patience и learning rate нужно вынести в общий конфигурационный файл.

Нельзя для отдельных моделей вручную подбирать более выгодные параметры обучения, 
если это не выделено в отдельную серию. Основное сравнение архитектур должно быть честным.

==================================================
5. СЕРИИ ЭКСПЕРИМЕНТОВ
==================================================

Все серии нужно проводить последовательно.

Сначала исследуется влияние каждого архитектурного параметра отдельно. 
В каждой серии изменяется только один параметр, остальные остаются равными значениям базовой модели.

После одиночных экспериментов создаются несколько комбинированных упрощенных моделей.

--------------------------------------------------
СЕРИЯ 0. БАЗОВАЯ МОДЕЛЬ
--------------------------------------------------

Цель:
получить контрольный результат, с которым будут сравниваться все измененные варианты.

Эксперимент:

exp00_baseline

Параметры:

- width_coefficient = 1.0
- depth_coefficient = 1.0
- стандартные expansion ratio
- use_se = True
- se_ratio = 0.25
- kernel_mode = "standard"
- head_channels = 1280
- input_size = 224

Базовую модель нужно обучать с нуля, чтобы сравнение с измененными архитектурами было корректным.

При желании отдельно можно сохранить старый результат готовой EfficientNetB0 с весами ImageNet, 
но он не должен использоваться как основной baseline для сравнения архитектур, обучаемых с нуля.

--------------------------------------------------
СЕРИЯ 1. ИЗМЕНЕНИЕ ШИРИНЫ СЕТИ
--------------------------------------------------

Цель:
исследовать, как уменьшение количества каналов влияет на точность и время обучения.

Эксперименты:

exp01_width_075
- width_coefficient = 0.75

exp02_width_050
- width_coefficient = 0.50

exp03_width_035
- width_coefficient = 0.35

Все остальные параметры должны совпадать с baseline.

При масштабировании числа каналов желательно использовать функцию округления, аналогичную EfficientNet, 
чтобы количество каналов оставалось кратным определенному divisor, например 8.

Необходимо сохранять фактическое количество каналов каждой стадии после округления в конфигурации модели 
или отдельном файле model_structure.json.

--------------------------------------------------
СЕРИЯ 2. ИЗМЕНЕНИЕ ГЛУБИНЫ СЕТИ
--------------------------------------------------

Цель:
исследовать влияние уменьшения числа повторений MBConv-блоков.

Эксперименты:

exp04_depth_080
- depth_coefficient = 0.80

exp05_depth_060
- depth_coefficient = 0.60

exp06_depth_040
- depth_coefficient = 0.40

Количество повторений в каждой стадии должно рассчитываться функцией масштабирования глубины.

Например:

repeats_scaled = ceil(depth_coefficient * repeats_original)

При этом в каждой стадии должен оставаться как минимум один блок.

Все остальные параметры должны совпадать с baseline.

--------------------------------------------------
СЕРИЯ 3. ИЗМЕНЕНИЕ EXPANSION RATIO
--------------------------------------------------

Цель:
определить, насколько можно уменьшить внутреннее расширение каналов в MBConv-блоках.

Эксперименты:

exp07_expansion_4
- во всех блоках, где стандартно expansion_ratio = 6, использовать 4

exp08_expansion_3
- использовать expansion_ratio = 3

exp09_expansion_2
- использовать expansion_ratio = 2

Для первой стадии, где expansion_ratio стандартно равен 1, можно оставить значение 1.

Все остальные параметры должны совпадать с baseline.

--------------------------------------------------
СЕРИЯ 4. ИЗМЕНЕНИЕ SQUEEZE-AND-EXCITATION
--------------------------------------------------

Цель:
оценить влияние механизма Squeeze-and-Excitation на точность и время обучения.

Эксперименты:

exp10_se_0125
- use_se = True
- se_ratio = 0.125

exp11_no_se
- use_se = False

Baseline использует:

- use_se = True
- se_ratio = 0.25

Все остальные параметры должны совпадать с baseline.

--------------------------------------------------
СЕРИЯ 5. ИЗМЕНЕНИЕ РАЗМЕРОВ ЯДЕР
--------------------------------------------------

Цель:
проверить, можно ли заменить более крупные depthwise-свертки 5 x 5 на 3 x 3.

Эксперимент:

exp12_all_kernels_3

Параметры:

- все depthwise-свертки используют kernel_size = 3;
- остальные параметры совпадают с baseline.

Стандартный baseline использует сочетание ядер 3 x 3 и 5 x 5.

--------------------------------------------------
СЕРИЯ 6. ИЗМЕНЕНИЕ ЗАКЛЮЧИТЕЛЬНОЙ ЧАСТИ СЕТИ
--------------------------------------------------

Цель:
исследовать влияние уменьшения числа каналов перед глобальным усреднением и классификатором.

Эксперименты:

exp13_head_640
- head_channels = 640

exp14_head_320
- head_channels = 320

При необходимости можно добавить:

exp15_head_160
- head_channels = 160

Но этот эксперимент можно оставить дополнительным и запускать только в том случае, 
если head_channels = 320 не приводит к слишком сильному падению точности.

Все остальные параметры должны совпадать с baseline.

--------------------------------------------------
СЕРИЯ 7. ИЗМЕНЕНИЕ РАЗРЕШЕНИЯ ВХОДНОГО ИЗОБРАЖЕНИЯ
--------------------------------------------------

Цель:
исследовать влияние уменьшения разрешения изображения на точность и время обучения.

Эксперименты:

exp16_resolution_192
- input_size = 192

exp17_resolution_160
- input_size = 160

exp18_resolution_128
- input_size = 128

Все остальные параметры должны совпадать с baseline.

Важно:
для каждого эксперимента pipeline загрузки данных должен автоматически 
использовать нужный image_size из конфигурации.

--------------------------------------------------
СЕРИЯ 8. КОМБИНИРОВАННЫЕ УПРОЩЕННЫЕ МОДЕЛИ
--------------------------------------------------

Эту серию нельзя окончательно задавать до анализа предыдущих результатов.

После завершения серий 1–7 необходимо выбрать изменения, которые дали наиболее выгодное соотношение:

- точность;
- время обучения.

После этого нужно сформировать примерно три комбинированные модели:

1. EfficientNet-Light
   Небольшое упрощение с минимальным снижением точности.

2. EfficientNet-Mini
   Среднее упрощение, ориентированное на баланс точности и времени обучения.

3. EfficientNet-Tiny
   Сильное упрощение, ориентированное на минимальное время обучения.

Предварительные варианты конфигураций можно использовать только как шаблон.

Пример Light:

- width_coefficient = 0.75
- depth_coefficient = 0.80
- expansion_ratio = 4
- use_se = True
- se_ratio = 0.25
- head_channels = 640
- input_size = 192

Пример Mini:

- width_coefficient = 0.50
- depth_coefficient = 0.60
- expansion_ratio = 3
- use_se = True
- se_ratio = 0.125
- head_channels = 320
- input_size = 160

Пример Tiny:

- width_coefficient = 0.35
- depth_coefficient = 0.40
- expansion_ratio = 2
- use_se = False
- all kernels = 3
- head_channels = 160 или 320
- input_size = 128

Окончательные параметры этих моделей должны выбираться на основании уже полученных экспериментальных данных.

==================================================
6. ТРЕБОВАНИЯ К СОХРАНЕНИЮ РЕЗУЛЬТАТОВ
==================================================

Для каждого эксперимента необходимо автоматически создавать отдельную папку.

Пример структуры:

results/
    exp00_baseline/
        config.json
        model_summary.txt
        model_structure.json
        history.csv
        history.json
        epoch_times.csv
        final_metrics.json
        test_results.json
        training_log.csv
        best_model.keras
        final_model.keras
        checkpoints/
        plots/
            accuracy.png
            loss.png

    exp01_width_075/
        ...

Названия файлов должны быть одинаковыми для всех экспериментов.

--------------------------------------------------
6.1. config.json
--------------------------------------------------

Файл должен содержать все параметры, необходимые для полного повторения эксперимента.

Обязательно сохранять:

- experiment_id;
- experiment_name;
- experiment_series;
- description;
- model_name;
- input_size;
- num_classes;
- width_coefficient;
- depth_coefficient;
- expansion_ratio;
- use_se;
- se_ratio;
- kernel_mode;
- head_channels;
- dropout_rate;
- batch_size;
- max_epochs;
- learning_rate;
- optimizer;
- loss;
- random_seed;
- train_directory;
- validation_directory;
- test_directory;
- количество изображений в train;
- количество изображений в validation;
- количество изображений в test;
- дата и время запуска;
- версия Python;
- версия TensorFlow;
- информация об используемом устройстве, если ее можно получить автоматически.

Нужно сохранять не только явно заданные параметры, но и фактически использованную конфигурацию.

--------------------------------------------------
6.2. model_summary.txt
--------------------------------------------------

Сохранить текстовый вывод:

model.summary()

Это позволит позднее проверить фактическую структуру модели.

--------------------------------------------------
6.3. model_structure.json
--------------------------------------------------

Сохранить структурированное описание модели:

- список стадий;
- число повторений;
- kernel_size;
- stride;
- expansion_ratio;
- input_filters;
- output_filters;
- use_se;
- se_ratio;
- фактические значения после применения width_coefficient и depth_coefficient.

Файл должен позволять понять архитектуру без повторного запуска кода.

--------------------------------------------------
6.4. history.csv
--------------------------------------------------

Это основной файл для последующего построения графиков.

Каждая строка соответствует одной эпохе.

Обязательные столбцы:

- epoch;
- accuracy;
- val_accuracy;
- loss;
- val_loss;
- epoch_time_seconds;
- learning_rate.

Пример:

epoch,accuracy,val_accuracy,loss,val_loss,epoch_time_seconds,learning_rate
1,0.65,0.61,0.89,0.94,14.52,0.001
2,0.74,0.69,0.68,0.75,13.91,0.001

Именно по этому файлу должны строиться графики accuracy и loss.

Графики не должны быть единственным источником данных.

--------------------------------------------------
6.5. history.json
--------------------------------------------------

Сохранить те же данные, что и в history.csv, в JSON-формате.

Это необязательно для анализа, но удобно для программной обработки и восстановления истории обучения.

--------------------------------------------------
6.6. epoch_times.csv
--------------------------------------------------

Сохранить время каждой эпохи отдельно.

Столбцы:

- epoch;
- epoch_time_seconds;
- cumulative_time_seconds.

Даже если время эпохи уже входит в history.csv, отдельный файл желательно оставить.

--------------------------------------------------
6.7. final_metrics.json
--------------------------------------------------

Сохранить итоговые значения:

- final_train_accuracy;
- final_val_accuracy;
- final_train_loss;
- final_val_loss;
- best_epoch_by_val_accuracy;
- best_val_accuracy;
- best_epoch_by_val_loss;
- best_val_loss;
- total_training_time_seconds;
- average_epoch_time_seconds;
- completed_epochs;
- stopped_early;
- experiment_status.

Нужно явно различать:

- результат последней эпохи;
- лучший результат по validation accuracy;
- лучший результат по validation loss.

--------------------------------------------------
6.8. test_results.json
--------------------------------------------------

После загрузки лучших весов выполнить оценку на тестовой выборке.

Сохранить:

- test_accuracy;
- test_loss;
- evaluated_model;
- best_checkpoint_path;
- test_samples;
- evaluation_date_time.

В дипломе основным итоговым показателем качества будет test_accuracy.

--------------------------------------------------
6.9. training_log.csv
--------------------------------------------------

Можно использовать стандартный CSVLogger TensorFlow/Keras.

Этот файл должен сохраняться параллельно с history.csv.

history.csv можно формировать самостоятельно после обучения или обновлять после каждой эпохи.

--------------------------------------------------
6.10. МОДЕЛИ И CHECKPOINTS
--------------------------------------------------

Необходимо сохранять:

- лучшую модель по val_loss или лучшие веса;
- финальную модель после завершения обучения;
- при необходимости промежуточные checkpoints.

Предпочтительный формат:

- best_model.keras;
- final_model.keras.

Если сохраняются только веса:

- best.weights.h5.

Критерий выбора лучшей модели должен быть одинаковым для всех экспериментов.

Рекомендуется:

monitor = "val_loss"
save_best_only = True
restore_best_weights = True

==================================================
7. ТРЕБОВАНИЯ К ГРАФИКАМ
==================================================

После каждого эксперимента автоматически строить два графика:

1. accuracy:
   - train accuracy;
   - validation accuracy;
   - ось X: номер эпохи;
   - ось Y: accuracy.

2. loss:
   - train loss;
   - validation loss;
   - ось X: номер эпохи;
   - ось Y: loss.

Графики сохранять в PNG.

Но код построения графиков должен читать данные из history.csv, а не использовать только объект History в памяти.

Нужно создать отдельный модуль или скрипт, например:

plot_history.py

Он должен уметь:

- построить графики одного эксперимента;
- повторно построить графики без обучения;
- изменить подписи и оформление;
- сохранить изображения в нужную папку;
- объединить несколько экспериментов на одном графике.

Также нужен скрипт:

compare_experiments.py

Он должен читать итоговые результаты всех экспериментов и строить сравнительные графики.

Минимально необходимые сравнительные графики:

1. test_accuracy для всех экспериментов;
2. total_training_time_seconds для всех экспериментов;
3. test_accuracy в зависимости от total_training_time_seconds;

9. CALLBACK ДЛЯ ИЗМЕРЕНИЯ ВРЕМЕНИ
==================================================

Нужно реализовать собственный callback, который:

- фиксирует начало обучения;
- фиксирует начало каждой эпохи;
- фиксирует конец каждой эпохи;
- рассчитывает время эпохи;
- рассчитывает общее время обучения;
- добавляет epoch_time_seconds в logs;
- сохраняет информацию даже при early stopping.

Пример логики:

class EpochTimeCallback(tf.keras.callbacks.Callback):
    def on_train_begin(...):
        сохранить время начала обучения

    def on_epoch_begin(...):
        сохранить время начала эпохи

    def on_epoch_end(...):
        вычислить время эпохи
        добавить logs["epoch_time_seconds"]

    def on_train_end(...):
        вычислить общее время обучения

Желательно использовать time.perf_counter().

17. ОЖИДАЕМЫЙ РЕЗУЛЬТАТ
==================================================

В результате должна получиться система, которая позволяет:

- запускать разные варианты архитектуры EfficientNet через конфигурации;
- автоматически обучать модели;
- сохранять полную историю обучения;
- сохранять точность, loss и время;
- восстанавливать графики без повторного обучения;
- сравнивать эксперименты;
- выбирать упрощенную архитектуру, которая обучается быстрее и сохраняет приемлемую точность.

Главная исследовательская логика диплома:

1. строится базовая модель;
2. отдельно исследуется влияние каждого архитектурного изменения;
3. сравниваются точность и время обучения;
4. выбираются наиболее удачные изменения;
5. создаются комбинированные упрощенные модели;
6. определяется вариант с наиболее подходящим балансом точности и времени обучения.
